# Как устроено

## Слои

| Пакет | Что это |
| --- | --- |
| `artifacts/api-server` | API: склад, букеты, аналитика, ассистент, боты |
| `artifacts/flower-stock` | интерфейс магазина (React) |
| `lib/db` | схема PostgreSQL (Drizzle) |
| `lib/api-spec` | `openapi.yaml` — источник правды для контракта |
| `lib/api-zod`, `lib/api-client-react` | сгенерированные схемы и хуки (руками не править) |
| `lib/integrations-openai-ai-server` | клиент OpenAI-совместимого SDK |
| `scripts` | сиды, проверки, замеры вёрстки |

## Правила, которые важно не нарушить

1. **Остаток меняется только операциями.** Никогда не вставляйте приходы с пустым
   `remaining_quantity` (сиды, импорт): ленивое восстановление партий размажет остаток и
   потеряет уже израсходованное.
2. **Схема — через Drizzle**: меняете `lib/db/src/schema/*`, затем
   `pnpm --filter @workspace/db run push`.
3. **Контракт — через спецификацию**: меняете `lib/api-spec/openapi.yaml`, затем
   `pnpm --filter @workspace/api-spec run codegen`. Сгенерированные файлы не правьте: их
   перезапишет следующая генерация.
4. **Проверять фактами.** Правка подтверждается скриптом, который измеряет (геометрия DOM,
   тела запросов, дельты остатков), а не «выглядит нормально».

## Ассистент и провайдер AI

Ассистент превращает фразу в план операций, спорные позиции уточняет и пишет в учёт только
после подтверждения. Работает он через любой OpenAI-совместимый провайдер; модель обязана
поддерживать вызов инструментов (function calling) — на этом держится разбор команд.

Провайдеров два:

- **платформенный** — из окружения (`OPENAI_*`), задаёт владелец сервиса. Магазину он
  недоступен: ключ не отдаётся наружу даже окончанием;
- **свой** — ключ магазина, вводится в разделе «Настройки».

Порядок обращения: свой ключ → платформенный → провайдера нет.

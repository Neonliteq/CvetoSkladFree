# Проверки

Проект проверяется скриптами, которые **измеряют**, а не «смотрят глазами». Каждая правка
подтверждается числами: геометрией DOM, телами запросов, дельтами остатков.

## Запуск

Сначала поднимите стенд (API и интерфейс), затем:

```bash
node scripts/src/status.mjs          # ревизия, ссылки, список проверок, правило журнала
node scripts/src/status.mjs --checks # серверные проверки подряд, с числом утверждений
node scripts/src/check-analytics.mjs # одна конкретная проверка
```

**Важно:** каждая проверка сама заливает демонстрационные данные, поэтому запускайте их
**по одной, последовательно**. Параллельный прогон перетрёт базу друг у друга.

## Что проверяется

| Область | Скрипт |
| --- | --- |
| Остатки, партии, сводка | `check-products-view.mjs`, `check-product-archive.mjs` |
| Операции и отмена | `check-movements-paging.mjs`, `check-movement-undo.mjs` |
| Букеты и сборка | `check-bouquet-production.mjs` |
| Аналитика | `check-analytics.mjs` |
| Ассистент и настройки AI | `check-assistant-batch.mjs`, `check-ai-settings.mjs` |
| Вход, роли, права | `check-auth.mjs` |
| Интерфейс (через браузер) | `check-*-ui.mjs` |

Скрипты `check-*-ui.mjs` управляют настоящим браузером через отладочный протокол: они
открывают страницу, нажимают кнопки и проверяют, что получилось. Нужен установленный
Chrome или Edge; путь задаётся переменной `EDGE_PATH`.

## Проверки, которым нужна живая модель

Часть проверок говорит с настоящим провайдером. Без ключа они не пройдут — это ожидаемо.
Проверка `check-ai-settings.mjs` поднимает **свою заглушку** провайдера, поэтому ключ ей не
нужен: она доказывает, что ассистент уходит на нужный адрес и с нужной моделью.
